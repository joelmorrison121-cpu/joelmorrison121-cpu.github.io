PLAYABLE DESKTOP BUILD / v2.0 RELEASED

AI Racer.

A 2D racing game in which neural-network drivers learn four circuits by neuroevolution, through selection and mutation across generations. Results are tested across five random seeds and on tracks the drivers never trained on.

  • Python
  • Pygame
  • Neuroevolution
  • unittest

My contribution: solo project. I designed and built the car physics, track and checkpoints, sensors, neural network and evolutionary trainer, using AI assistance for explanations and debugging.

GitHub repository ↗Read the build notes ↗
What works & what I learned +

Works: four tracks, including curved ones built from a centre-line path, plus checkpoints at any angle, a lap-time reward, save/resume and live progress graphs. On the flowing track all five seeds learned a lap, at generation 15.8 ± 3.1. Champions transfer to an unseen oval (5/5) but not yet to hairpins (0/5). Twenty unit tests pass.

Learned: fixed-timestep simulation, ray-cast sensors and fitness design. I also learned to inspect a network's inputs and outputs before assuming the physics is broken. One early AI pressed the accelerator and the brake at the same time.

Desktop app (Python 3.10+, pygame-ce). The README covers setup, controls and training. Download the v2.0 source ZIP ↓

03 / LIVE HACKATHON BUILD

Leap

A wait-or-switch commute planner for Dublin. It compares bus, Luas and walking door to door, including walks and waits, and shows the exact extra wait at which switching becomes quicker.

Manus AI Dublin Build Challenge · 8 Oct 2026

  • Web app
  • Built with Manus
  • No login
Open live demo ↗

My contribution: my own build. Our team of four each built a separate app, and the team then put forward one entry, a teammate's project called Kickstart, as its submission.

What works & what I learned +

It has 33 places across Dublin with estimated journeys between any two, editable time assumptions, and a break-even wait for switching. You can also set priorities (speed or less time outside), add an arrival deadline and share a comparison link. Try DCU Glasnevin → St Stephen’s Green and raise the extra wait to 20 minutes.

Journey times are illustrative estimates, not a live transport feed, and the app says so on the page. It has no live arrivals, weather or city-wide routing.

Learned: building four prototypes in parallel and then letting the AI judge them broke our team’s indecision quickly. Taking Leap from first idea to a finished interface also taught me how to steer an AI agent through a whole build.

04 / PROTOTYPE · HACKATHON

Split

A shared-bill prototype with per-person links and a tested Node.js backend.

BUILD IRL Vol. 1 · Team hackathon build

  • Node.js
  • JavaScript
  • React frontend
  • Mock settlement
Frontend demo ↗Backend repository ↗

My contribution: I was responsible for the React frontend; the live demo is linked above.

What works & what I learned +

The backend creates bills, issues unique payer links, tracks payment state and handles duplicate, invalid or expired requests. Its ten automated tests pass locally using mock settlement.

Frontend and backend both existed, but we did not connect them into one reliable payment journey. Embedded wallets, live on-chain payments and persistent storage were not implemented.

Working in a five-person team under a short deadline taught me to agree API contracts early, cut scope deliberately and leave time for integration.

Hackathon prototype, not a production payments service. The frontend and backend were not joined up before the deadline, data is held in memory, and settlement is mocked.
